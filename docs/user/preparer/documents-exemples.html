Préparer et suivre

Utiliser les modèles fournis

L’onglet Documents exemples réunit les emplacements prévus pour les guides de correction et de pseudonymisation, ainsi que les documents de protection des données. Il est distinct de vos documents du projet et des corpus d’exercice.

Les quatre fichiers fournis actuellement ne sont pas encore des modèles rédigés : ils contiennent seulement leur titre et la mention À venir. Ils ne fournissent donc ni consignes prêtes à appliquer, ni déclaration ou notice de consentement utilisable pour votre enquête.

Pour préparer votre terrain, utilisez les documents validés par votre organisme. Les consignes de votre délégué à la protection des données (DPO) restent prioritaires ; la présence d’un fichier dans cet onglet ne constitue pas une validation de votre démarche.

Consulter les documents exemples

  1. Ouvrez un corpus, puis cliquez sur Préparer et suivre dans la barre supérieure.
  2. Dans les onglets à icônes de gauche, choisissez Documents exemples. Le survol d’une icône affiche son nom.
  3. Cliquez sur un fichier, ou entrez d’abord dans le dossier DPO. La fiche du fichier et son texte apparaissent à droite.
  4. Depuis le dossier DPO, cliquez sur Documents exemples dans le chemin au-dessus de la liste pour revenir au premier niveau.

La consultation ne modifie aucun exemple et n’ajoute rien à votre corpus. Les deux onglets documentaires conservent chacun leur dossier pendant la session.

La mention À venir. fait partie du fichier : elle ne signale pas un chargement en cours. Cliquer sur Actualiser ne complète pas le document et ne télécharge pas de nouveau modèle.

Un guide écrit n’applique aucun réglage dans SonalPi. Votre propre guide de pseudonymisation peut décrire des consignes d’équipe, mais les remplacements doivent être définis et contrôlés dans l’outil de pseudonymisation.

Enregistrer une copie sans modifier l’exemple

La copie permet de récupérer le fichier tel quel. Dans l’état actuel, elle contiendra elle aussi le titre et « À venir. », pas un modèle complété.

  1. Sélectionnez le fichier voulu dans Documents exemples.
  2. Cliquez sur Enregistrer une copie.
  3. Choisissez un dossier sur votre ordinateur et un nom distinct, par exemple Consignes-correction-associations.txt, puis enregistrez.
  4. Attendez le message Une copie exacte du fichier original a été enregistrée.
  5. Retrouvez cette copie dans votre gestionnaire de fichiers et ouvrez-la avec une application adaptée pour rédiger votre propre document.

Le format ne change pas lors de la copie. Pour ces fichiers TXT, un éditeur de texte convient. Vous pouvez aussi rédiger directement votre document dans votre traitement de texte habituel, sans partir d’un fichier vide fourni.

L’exemple livré avec SonalPi reste inchangé. Cet onglet ne propose ni modification du contenu, ni ajout, ni suppression, ni ouverture du fichier d’installation dans une autre application. Pour modifier un document, travaillez sur votre copie ; un double-clic sur l’exemple ne l’ouvre pas dans un éditeur externe.

Si vous annulez le choix de destination, aucune copie n’est créée. En cas de message d’échec, vérifiez que le dossier choisi est accessible, puis recommencez. Ne considérez pas la copie comme enregistrée avant la confirmation.

Conserver votre document dans le projet

Une copie enregistrée ailleurs n’apparaît pas automatiquement dans Documents du projet. Les exemples et vos fichiers personnels restent séparés.

Dans un corpus local, rédigez votre document puis ajoutez-le avec Documents du projet → Ajouter un fichier. Par exemple, vous pouvez y ranger les consignes de correction rédigées pour Enquête dans les associations. Cet ajout crée une nouvelle copie dans le corpus : pour la faire évoluer ensuite, ouvrez celle du corpus, pas le fichier resté ailleurs.

Sur Nextcloud, déposez votre document dans le dossier documentaire du corpus depuis le navigateur, puis actualisez la liste dans SonalPi. Sur GitLab, les documents du projet ne sont pas disponibles dans cet outil.

Réunir les documents du projet explique l’ajout local, le classement et les différences avec un corpus distant. Pensez aussi à sauvegarder vos documents personnels : ils ne seront pas récupérés en consultant les exemples d’origine.

Retrouver les exemples avec un corpus distant

Les documents exemples sont fournis avec l’application sur votre poste, indépendamment du corpus ouvert. Ils restent consultables et copiables avec un corpus local, Nextcloud ou GitLab, même si la connexion au serveur est interrompue. Cela ne rend pas les documents du projet distant disponibles hors ligne.

Si vous ne retrouvez pas un fichier, vérifiez l’onglet et le dossier affichés, puis cliquez sur Actualiser. Une modification de votre copie personnelle ne doit pas apparaître ici : rouvrez cette copie ou le document que vous avez ajouté au projet.
